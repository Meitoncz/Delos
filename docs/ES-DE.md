# ES-DE shortcuts

Delos can write a small `.art` file for any game of a paired PC (game context menu → **Create ES-DE
shortcut**, [GUI.md](GUI.md#es-de-shortcuts)). ES-DE lists the file as a game of a custom system and, when
the user starts it, opens it with Delos (`ShortcutTrampoline`), which wakes the PC if needed and starts the
stream with the game's own settings (`GameLauncher.startIntent`). Nothing else is installed or registered:
the `.art` file is the link.

Status of this document: the file format and the Delos side are exercised by unit tests
(`ArtFileTest`: the content Delos writes is read back by the parser `ShortcutTrampoline` uses). The ES-DE
configuration below follows ES-DE's own documentation (sources at the end) and has **not been run on a
device**; every statement that depends on ES-DE's behavior is marked **UNVERIFIED**.

## The `.art` file

Text, UTF-8, one `[key] value` pair per line; blank lines and lines starting with `#` are comments. Any other
line makes the file invalid (a toast, nothing starts).

```
# Delos app entry
# Generated by Delos for Android

[host_uuid] 123e4567-e89b-12d3-a456-426614174000
[host_name] Living room PC
[app_uuid] 9a1c5a25-58fe-40e0-b9aa-7d3f00000001
[app_name] Desktop
```

| Key | Meaning |
| --- | --- |
| `host_uuid` | UUID of the paired PC (as Delos knows it). Wins over `host_name`. |
| `host_name` | The PC's name; used to find the PC only when there is no `host_uuid`. |
| `app_uuid` | The game's UUID on the PC. Wins over `app_id`. |
| `app_name` | The game's name (shown in toasts; when it is the only game key the PC's cached app list is searched for it, case-insensitively). |
| `app_id` | The game's numeric id. Delos writes it only for a game without a UUID (older servers). |

Writer and parser live in `utils/ArtFile.kt` (`artFileContent`, `artFileName`, `parseArtFile`);
`ShortcutTrampoline` calls the same `parseArtFile`. Values are written as one line (line breaks and control
characters become one space, so a name cannot add keys); `[` and `]` inside a value are fine because only the
first word of a line is the key.

The file is named `<game name>.art`: `/ \ : * ? " < > |` and control characters become spaces, runs of
spaces collapse, spaces and dots are trimmed from both ends, at most 120 characters (Unicode stays). ES-DE
shows the name without the extension as the game's title. A file of that name is overwritten, so two games with
the same name (for example `Desktop` on two PCs) share one file in the same folder: use one folder per PC, or
rename one of the games in the PC's app list.

## Where the files go

The folder is the one the user picks in Android's folder picker the first time (Settings → Devices → ES-DE →
**ES-DE shortcut folder** changes it). Pick the folder of the custom system below: `<ES-DE ROMs folder>/delos`
(create it in the picker's *New folder*). Delos keeps access with a persisted URI permission and writes with
Storage Access Framework calls only, so it needs no storage permission.

## ES-DE configuration

ES-DE launches Android apps with Intents, configured by two files in `ES-DE/custom_systems/` of the ES-DE
application data directory (the user guide describes `es_systems.xml` and `es_find_rules.xml` there; on
Android both are read from that directory).

`es_find_rules.xml` defines the "emulator" `DELOS`: the activity that receives the file. The activity must be
named, because the package's default activity (the launcher) does not read `.art` files.

```xml
<?xml version="1.0"?>
<ruleList>
    <emulator name="DELOS">
        <rule type="androidpackage">
            <entry>io.github.meitoncz.delos/com.limelight.ShortcutTrampoline</entry>
            <entry>io.github.meitoncz.delos.debug/com.limelight.ShortcutTrampoline</entry>
        </rule>
    </emulator>
</ruleList>
```

`es_systems.xml` defines the system. Its extensions are case-sensitive on Android.

```xml
<?xml version="1.0"?>
<systemList>
    <system>
        <name>delos</name>
        <fullname>Delos</fullname>
        <path>%ROMPATH%/delos</path>
        <extension>.art .ART</extension>
        <command label="Delos">%EMULATOR_DELOS% %ACTION%=android.intent.action.VIEW %DATA%=%ROMPROVIDER%</command>
        <platform>pc</platform>
        <theme>pc</theme>
    </system>
</systemList>
```

- `application id`: `io.github.meitoncz.delos` (release) and `io.github.meitoncz.delos.debug` (debug build);
  the activity is `com.limelight.ShortcutTrampoline`, exported, in both.
- `%ACTION%=android.intent.action.VIEW` is required: `ShortcutTrampoline` reads a `.art` file only for
  `ACTION_VIEW` with a data URI.
- `%DATA%=%ROMPROVIDER%` passes the file as a `content://` URI of ES-DE's FileProvider and lets ES-DE grant
  Delos read access to that one file (ES-DE's FileProvider mode). `ShortcutTrampoline` opens the URI with
  `ContentResolver.openInputStream`. Alternative: `%DATA%=%ROMSAF%` (a
  `content://com.android.externalstorage.documents/...` URI); Delos can read it only when it holds access to
  the folder, which it does for the folder it picked itself, so both must be the same folder. Do not use
  `%DATA%=%ROM%`: a plain path has no scheme and cannot be opened.
- `%MIMETYPE%` is not set: ES-DE's default type (`application/octet-stream`) matches the filter's `*/*`.
- ES-DE's ROMs folder is `%ROMPATH%`; for a relocated folder use an absolute `<path>` as ES-DE's Android
  document describes. `<platform>` and `<theme>` `pc` name ES-DE's bundled PC system (present in its Android `es_systems.xml`).
- Create one shortcut before opening the system in ES-DE (an empty folder shows no games); restart ES-DE after
  changing the two files.

## What Delos does with the file

`ShortcutTrampoline` (`ACTION_VIEW`, data URI) parses the entry, finds the PC in Delos' own list by UUID (or
name), shows the Delos launch scene, wakes the PC when needed and starts the game; per-game settings apply as
for a start from Home. Specifics (docs/GUI.md "Stream"): a bad file or an unknown PC ends with a toast; a launch
of another game while one runs never quits the running game, it opens that PC's games with a toast. A `.art`
launch from outside Delos is one click (no confirmation), unlike `art://` links.

Manifest: the filter of `ShortcutTrampoline` accepts `content` and `file` URIs, any host, any MIME type and a
path matching `.*\.art` (the path is the decoded URI path and must end in a lower-case `.art`). It matters only
for implicit intents ("Open with" from a file manager); the ES-DE configuration above names the activity, so
the filter is not consulted. No manifest change was needed. A `content://` URI whose path does not end in
`.art` (opaque document ids) would not match an implicit intent, and cannot be matched without matching every
file; the explicit activity of the find rule is the way around that. A `file://` URI without a type from an
implicit intent probably does not match (the filter declares a type): **UNVERIFIED**, unused here.

## UNVERIFIED

Not run on a device; confirm on the Odin with ES-DE installed:

1. That ES-DE reads `custom_systems/es_find_rules.xml` and `es_systems.xml` as above on the current Android
   release, and that `%EMULATOR_DELOS%` resolves to the debug build when only that is installed.
2. That `%DATA%=%ROMPROVIDER%` reaches `ShortcutTrampoline` with `ACTION_VIEW`, the content URI and a read grant
   the activity can use (`SecurityException` is caught and shown as a toast; an unreadable file never crashes it).
3. ES-DE's intent flags: ES-DE's own default is used (the `%ACTIVITY_CLEAR_TASK%`/`%ACTIVITY_CLEAR_TOP%`
   variables are not set). `ShortcutTrampoline` is `noHistory` and starts the stream itself, so the expected
   result is the Delos launch scene over ES-DE and ES-DE behind the stream; whether Back returns to ES-DE is
   not checked.
4. That ES-DE lists the files (extensions `.art .ART`, case-sensitive) and shows the file name as the title.
5. The `%ROMSAF%` variant with Delos' persisted access to the same folder.
